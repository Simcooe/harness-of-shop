**Shopping Agent：面向多轮导购的 Harness 设计与过程评测**　2026.10 - 至今

**项目背景**：针对购物 Agent 在多轮导购中未经用户确认即下单、难以利用用户画像的问题，在 ShopSimulator 中不改模型权重，以评测驱动 Harness 迭代。

- **Harness 架构设计**：将单 Agent 拆分为导购与买手：导购负责对话与决策，买手在独立会话中检索、比对商品，两侧只传递经页面原文核验的需求单与候选单，下单须用户明确确认；严格成功率 50% → 90%，用户确认后买对 22% → 56%
- **过程评测体系**：不依赖环境奖励，以原子约束 rubric 逐条核验所购商品，新增“用户确认后买对”指标；LLM 评审按 5 个维度评估轨迹，以下单前用户原话附注与分数上限校准评审盲区；对模拟用户做质检，修正其凭空追加购买条件的问题（50 题中 22 题 → 5 题）
- **失败归因与迭代**：以里程碑漏斗定位首个错误动作，并按约束来源（用户原话 / 画像）分组核验，定位画像场景的两类主因：近期搜索未被利用、被无关偏好品牌带偏；据此设计画像分级（近期搜索作为约束，长期偏好仅作排序参考），严格成功率 66% → 81%

## 数字来源（面试时用）

- 第一条：ShopSimulator 论文的多轮协议（40 个回合；模拟用户只在被问到时说细节，需求没问全就拒绝购买），200 题测试集，agent 模型 DeepSeek-V4-Flash，每组跑一次。50% / 22% 是原生 Agent（通用 agent 框架加环境适配层），90% / 56% 是导购 + 买手。中间的插件版本是 84% / 36%，对话中没经用户确认就下单 83 次，分工之后是 0 次。
- 第二条：评审校准前，插件版本的决策质量 1.62 分；加上附注和打分上限后是 1.25 分（它有 78 题在用户还在提问时就下单，原来评审几乎不扣分）。22 → 5：画像开发集 50 题里，模拟用户把自己没想好的细节当成购买条件的题数。
- 第三条：画像设置（模拟用户只知道一句简版需求，细节记在用户画像里，agent 能看到画像），从官方画像测试集抽 200 题。分工导购 66% → 画像分级 81%（36 题变好、7 题变差）；用户确认后买对 61% → 72%；画像搜索词里的要求，买到的商品满足率 82% → 91%；拿无关品牌去搜 25 → 15 题。
